# Lime Glow Design System

블랙 위에는 라임 빛을, 민트 화이트 위에는 제품 화면 같은 흰 UI 카드를 둡니다. 각 장은 웹사이트 한 섹션처럼 상단 내비 바를 달고, **가운데 헤드라인 + 한 구절 강조 + 큰 숫자 + 짧은 UI 목업**으로 말합니다. 글로우와 그림자는 이 디자인의 언어이지만, 정해진 자리와 강도에서만 씁니다.

## 0. 작업 순서 (반드시 이 순서)

1. 포맷을 고르고, 템플릿 HTML과 `assets/lime-glow.css`를 **같은 결과물 폴더**에 복사한 뒤 `<link href="../assets/lime-glow.css">`를 `href="lime-glow.css"`로 바꾼다.
   - 슬라이드 덱(16:9, 1280×720): `templates/deck.html`에서 시작
   - 세로 롱페이지(웹뷰·한 장 PDF·모바일 공유): `templates/doc.html`에서 시작
2. 내용을 슬라이드/섹션 단위로 나눈다. **1장 1메시지**로, §5 아키타입 중 하나에 배정하고 다크(`.dk`)·라이트(`.lt`) 순서를 먼저 정한다. 액센트 장(`.lm`)은 가장 강한 시장·지표 장 1곳에만 둔다.
3. 템플릿 블록을 복제해 텍스트만 바꾼다. 글로우 레이어는 템플릿의 위치값을 그대로 쓰고, 옮길 때도 화면 밖에 중심을 둔다.
4. `python3 scripts/render.py <file.html> [out_dir]`로 렌더한다.
5. **반드시 PNG를 열어서 직접 본다.** 덱은 `_check_<name>/sheet.png`와 개별 `sNN.png`, 문서는 `full.png`. PDF도 한 장 열어 글로우가 남아 있는지 본다. §9 체크리스트로 검수하고 고친 뒤 다시 렌더한다.

## 1. 원칙 5가지

1. **웹사이트형 장.** 모든 장(문서는 모든 섹션) 위에 `.nav`(좌측 로고 마크 + 이름, 우측 대문자 탭 4~6개, 현재 섹션 `.on`에 1.5px 밑줄)를 둔다. 탭 이름은 덱의 실제 섹션 구조와 맞춘다.
2. **다크와 라이트를 교차.** 표지·팀·원칙·마무리는 다크(`--night`), 문제·플랫폼·재무 표는 라이트(`--paper`). 같은 톤을 3장 넘게 연속으로 두지 않는다. 라임 그라데이션 바탕의 `.lm` 장은 덱·문서 전체에 1장.
3. **빛은 배경에만, 장당 하나.** 표지는 `.curtain`, 다크 장은 `.glow` 또는 `.ring` 1개, 라이트 장은 `.tint` 1개. 중심은 항상 화면 모서리 바깥에 두고 텍스트 뒤를 밝히지 않는다(§2-2 강도표).
4. **강조는 한 구절.** 헤드라인에서 한 구절만 `.hl`로 칠한다(다크 위 `--lime`, 라이트 위 `--leaf`, 액센트 장 위 `--moss`). 라임으로 면을 채우는 곳은 칩 점·토글 ON·강조 열 정도의 작은 요소뿐이다.
5. **숫자와 제품 화면이 근거.** 주장 옆에는 큰 숫자(`.num`, Geist 500) 1~2개 또는 흰 UI 카드 목업 하나를 붙인다. 목업은 실제 앱 화면처럼 짧은 라벨·토글·체크 행으로만 구성하고 긴 문장을 넣지 않는다.

## 2. 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--night` | #060706 | 다크 장 바탕 |
| `--coal` / `--coal2` | #101210 / #181b18 | 다크 위 카드·노드 (`.dkc`, `.node`) |
| `--paper` | #f4f7f2 | 라이트 장 바탕 (민트 기운의 흰색) |
| `--white` | #fff | UI 카드·표 컨테이너 |
| `--ink` / `--sub` | #0c0f0c / #687068 | 본문 / 보조 (다크 위 보조 `--subD` = 흰색 56%) |
| `--hair` / `--hairD` | rgba(12,24,12,.09) / rgba(255,255,255,.10) | 1px 헤어라인 |
| `--lime` | #b9f27e | 글로우 코어, 다크 위 강조 텍스트, 다크 위 토글 ON |
| `--leaf` | #4c9a2a | 라이트 위 강조 텍스트, 체크, 탭 밑줄, 커넥터 |
| `--mint` | #e3f3d6 | 칩, 강조 열, 강조 체크 행 |
| `--mint2` | #cfeeb4 | 액센트 장(`.lm`) 바탕 상단 |
| `--moss` | #2c6b17 | 액센트 장 위 강조 텍스트 |

**유채색은 이 초록 5개뿐이다.** 파랑·보라·청록 그라데이션, 무지개 차트는 쓰지 않는다. 브랜드 색이 필요하면 `--lime`·`--leaf`·`--mint`·`--mint2`·`--moss`를 같은 색상 계열의 밝기 단계로 함께 바꾼다.

### 2-1. 글로우 규칙 (전부 gradient — `filter:blur` 금지, PDF에서 사라짐)

| 레이어 | 어디에 | 강도(알파) | 배치 |
|---|---|---|---|
| `.curtain` | 표지·문서 히어로만 | 주름 .22 / .18 / .12, 좌우 가장자리 .30 | 화면 전체. 가운데 46%×62% 타원은 거의 검정으로 눌러 텍스트 자리를 비운다 |
| `.glow` (760px) / `.glow.sm` (420px) | 다크 장 1개 | `--g-soft` .18 → 45% 지점 .08 → 0 | 중심이 화면 밖(모서리에서 -300~-440px) |
| `.ring` | 마무리 장·문서 마지막 섹션 | `--g-line` .50의 얇은 고리 | 우하단 모서리 밖, `.glow`와 겹쳐서 |
| `.tint` (900px) | 라이트 장 1개 | `--g-tint` .55 → .22 → 0 (민트) | 우상단 또는 좌하단 모서리 밖 |
| `.gico` | 다크 위 아이콘 그리드 | `--g-core` .34, 지름 160px | 아이콘 칩 뒤에만 |
| `.node .mk` | 플로우 중앙 노드 | .35 | 노드 마크 뒤에만 |

- 강도를 올리고 싶으면 알파가 아니라 **글로우 위치를 화면 쪽으로 40~80px 당긴다.** 알파 .4 이상(커튼 제외)은 쓰지 않는다.
- 텍스트·숫자 바로 뒤에 글로우 중심이 오면 실패다. 글로우는 빈 영역(모서리, 표 아래 여백)을 채우는 용도다.
- 텍스트에는 `text-shadow`·네온 효과를 주지 않는다.

### 2-2. 그림자 규칙

- `--sh`(작은 카드)와 `--sh-lg`(큰 카드·표)만 쓰고, **라이트 장 위의 흰 카드에만** 준다.
- 다크 장 카드는 그림자 대신 `inset 0 0 0 1px var(--hairD)` 테두리로 분리한다. 예외는 라이트 장 위의 다크 노드(`.node`) 하나.
- 체크 행(`.crow`)·칩·정보 타일(`.info`)에는 그림자를 주지 않는다(카드 안의 그림자 금지).

## 3. 타이포 스케일

폰트는 Pretendard(한글·본문)와 Geist(영문 디스플레이·숫자·라벨) 두 가지다. Geist는 원본 레퍼런스의 유료 네오 그로테스크(Aeonik·General Sans 계열)를 대신하는 무료 Google Font다. `<head>`에 두 링크를 반드시 넣는다. 한글은 `word-break:keep-all`.

| 역할 | 덱(1280) | 문서(900) | 클래스 |
|---|---|---|---|
| 표지 디스플레이 | 78–128px / 500, 강조 구절은 400 | 60px | `.disp` + `.hl` |
| 한글 헤드라인 | 36–40px / 600 / -0.045em | 30px | `.h` (강조 `.hl`) |
| 대형 숫자 | 84–132px / 500 / -0.05em | 72–96px | `.num` |
| 카드 제목 | 14–17px / 600 | 14–15px | `.ko` 또는 inline |
| 본문/서브 | 15–17px | 14.5–15px | `.sub` |
| 캡션 | 13px | 13px | `.cap` |
| 라벨 | 10.5px Geist 500 대문자 자간 .08em | 동일 | `.lab` |
| 내비 탭 | 10.5px Geist 500 대문자 자간 .07em | 동일 | `.tabs` |
| 페이지 번호 | 11.5px Geist 500 | — | `.micro.pg` |

- 숫자의 영문 단위(K·M·%)는 숫자의 약 55~60%(`12<span style="font-size:52px">K</span>`). 한글 단위(조·억·명)는 `<span style="font-family:Pretendard;font-weight:600;font-size:…;letter-spacing:-.04em">억</span>`처럼 Pretendard로 따로 감싼다.
- 700 이상, 이탤릭, 밑줄은 쓰지 않는다. 표지 영문 디스플레이의 강조 구절만 400으로 한 단계 가볍게 한다.

## 4. 컴포넌트

- **내비 `.nav`**: `.logo`(20px 원형 마크 SVG + 이름 14px 600) + `.tabs`. 다크 장 마크는 `--lime`, 라이트 장은 `--leaf`, 액센트 장은 `--moss`. 실제 브랜드 로고는 넣지 않는다.
- **칩 `.chip`**: 9px 라운드의 옅은 민트 사각 캡슐. `.dot`으로 상태 점, `.ln`은 아웃라인 메타(날짜·장소). 다크 위에서는 자동으로 라임 10% 바탕 + 라임 글자. 한 줄에 2~3개.
- **UI 카드 `.card` / `.card.lg`**: 흰 바탕, radius 16/22, `--sh`/`--sh-lg`. 안에는 `.dkc` 헤더 한 줄(라벨 + 라임 숫자), `.crow` 체크 행 3~4개(`.ck` 체크, `.ck.off`, `.tg`/`.tg.on` 토글, 강조 행 `.crow.on` 1개), `.bar` 진행 막대, `.ph` 스켈레톤 줄만 쓴다.
- **플로우**: 입력 `.card` 2개 → 다크 `.node`(마크 + 이름 + 캡션) → 출력 `.card` 2개. 위에 `.chip`(단계), 아래에 `.pillk`(검은 캡슐, 사람 검토). 커넥터는 `.flow-svg` 안의 베지어 path — 입력 쪽 점선, 출력 쪽 `.on` 실선 `--leaf`.
- **표 `.tbl`**: 흰 컨테이너 radius 22 + `--sh-lg`. `.tr.th` 헤더는 대문자 라벨, 행은 헤어라인만. 강조 열 하나만 `.hc`(민트 세로 띠, 위아래 라운드). 세로선·지브라 금지.
- **대형 숫자 블록**: `.lab` → `.num` → `.cap` 순서. 두 개를 세로로 쌓을 때는 사이에 1px 헤어라인.
- **정보 타일 `.info`**: 액센트 장 위의 반투명 흰 타일(블러 없음). 제목 `b` 한두 줄 + 하단 `.cap`. 3개 가로 배열.
- **인물 자리 `.face`**: 회색조 그라데이션 + 실루엣 + `<em>이미지 자리</em>`. 실제 사진을 넣을 때도 흑백으로 바꾸고 radius 14 유지. 이름 16px 600 → `.micro` 직함 → `.cap` 한 줄 경력.
- **글로우 아이콘 `.gico`**: 다크 위 52px 라운드 칩 + 라임 1.6px 선 아이콘 + 뒤 글로우. 4열 `.cols`(헤어라인 세로 구분)에서만 쓴다. 아이콘은 `assets/icons.md`.

## 5. 아키타입 (템플릿에 전부 있음)

**덱 `templates/deck.html`**
1. **Cover**(다크 · `.curtain`): 가운데 영문 디스플레이 2줄(첫 구절 라임), 한글 서브 2줄, 하단 가운데 칩 2개.
2. **Problem + Number**(라이트 · `.tint` 우상단): 좌측 라벨·헤드라인·서브, 아래 112px 대형 숫자 + 캡션. 우측 `.card.lg` 목업(다크 헤더 + 체크 행 4 + 막대).
3. **Platform Flow**(라이트 · `.tint` 좌하단): 가운데 헤드라인, 입력 카드 2 → 다크 노드 → 출력 카드 2 플로우.
4. **Market**(액센트 `.lm`): 좌측 헤드라인, 우측 88px 숫자 2개(헤어라인 구분), 좌하단 파이프라인 `.info` 3개. 덱당 1장.
5. **Team**(다크 · `.glow` 좌상단): 좌측 헤드라인 + 우측 서브, 아래 인물 자리 4열.
6. **Financials**(라이트 · `.tint` 우하단): 가운데 헤드라인, `.tbl` 표(강조 열 1개), 좌하단 가상 수치 각주.
7. **Principles**(다크 · `.glow` 하단): 헤드라인 + 서브, `.gico` 4열 + 헤어라인 세로 구분.
8. **Closing / Ask**(다크 · `.glow` + `.ring` 우하단): 좌측 문장 2줄, 우측 132px 목표 숫자, 좌하단 연락 칩.

**문서 `templates/doc.html`**: Hero(다크, 커튼, 하단 스탯 3열) → Problem(라이트, 숫자 + UI 카드) → Platform(라이트, 플로우) → Market(액센트, 숫자 2 + 정보 타일 3) → Financials(라이트, 표) → Team + Ask(다크, 인물 4 + 목표 숫자 + 링).

## 6. 레이아웃 규칙

- **덱 좌표계**: 내비는 left/right 48px, top 24px. 콘텐츠는 left/right 72px, 헤드라인 top 100~124px, 하단 여백 44~60px. 페이지 번호 `.pg` 우하단(48, 24), 각주 `.note` 좌하단. 표지에는 번호를 넣지 않는다.
- **정렬 두 가지만**: (a) 가운데 정렬 — 헤드라인 + 서브를 가운데에 두고 아래에 플로우·표 같은 넓은 시각물. (b) 좌측 정렬 — 좌측 헤드라인, 우측 서브(폭 330px, `align-items:flex-end`) 또는 우측 카드/숫자.
- **카드 폭**: UI 카드 240~420px, 표는 좌우 200px 들여서 880px 안쪽. 화면을 꽉 채우는 카드는 만들지 않는다 — 바탕과 글로우가 보여야 한다.
- **간격**: 카드 사이 10~14px, 헤드라인과 시각물 사이 40~80px. 문서 섹션은 radius 24, 사이 10px, 안쪽 좌우 44px.
- **줄바꿈은 직접 정한다**: 헤드라인·서브는 `<br>`로 의미 단위에서 끊는다. 숫자·통화·날짜에는 `white-space:nowrap`.

## 7. 카피 규칙

- 헤드라인은 **주장 + 근거 범위** 구조로 쓴다. 예: "하나의 AI 엔진이 **모든 재무 업무**를 연결합니다", "연말까지 **월 매출 4억**, 플랫폼 하나로 확장합니다". 강조는 한 구절.
- 영문은 표지 디스플레이, 내비 탭, 라벨(`Problem`, `Input 01`, `Metric`)에만 쓴다. 본문·캡션·카드 내용은 한글.
- 숫자를 앞세우고 캡션에 출처나 "가상 수치"를 반드시 붙인다.
- UI 카드 문구는 기능명 6~12자(“세금계산서 자동 매칭”). 문장형 설명 금지.
- 근거 없는 최상급("국내 유일", "업계 최고")은 쓰지 않는다.

## 8. 금지 사항 (생성형 티가 나는 것)

- `filter:blur`·`backdrop-filter` 글래스모피즘, 텍스트 글로우·네온 그림자
- 텍스트 뒤를 지나는 밝은 글로우, 장당 글로우 2개 이상(마무리 장의 glow+ring 조합만 예외), 라이트 장에 라임 원형 글로우
- 라임으로 넓은 면 채우기, 라임 버튼·라임 박스 남발, 초록 외 유채색(파랑·보라·청록 그라데이션)
- 다크 위 카드에 드롭섀도, 카드 안 요소에 그림자, 카드 안의 카드 안의 카드
- 이모지, 컬러·3D 아이콘, 스톡 사진, 실제 브랜드 로고
- 균등 카드 4개 이상 나열(팀·원칙 4열만 허용), 불릿 5개 이상, 긴 설명 문장
- 700 이상 굵기, 이탤릭, 밑줄, 표 격자·지브라

## 9. 검수 체크리스트 (렌더 PNG를 보면서)

- [ ] 텍스트가 카드·화면 밖으로 넘치거나 겹치지 않는다. 특히 표지 디스플레이 폭, 표 마지막 행, 내비 탭.
- [ ] 한글이 어절 중간에서 끊기지 않고, 숫자·통화가 두 줄로 갈라지지 않는다.
- [ ] 장마다 글로우 레이어가 1개(마무리만 2개)이고, 글로우 중심이 텍스트 뒤에 있지 않다.
- [ ] PDF 한 장을 열어 커튼·글로우·그림자가 PNG와 같게 남아 있다.
- [ ] 다크·라이트가 교차하고 `.lm` 액센트 장은 1장뿐이다.
- [ ] 내비 `.on` 탭이 그 장의 섹션과 맞고, 페이지 번호가 `NN / 총장수`로 맞다.
- [ ] Geist가 로드됐다(숫자 1·4의 모양이 Inter·Arial과 다르면 OK). 안 보이면 링크·네트워크 확인.
- [ ] 가상 수치에 표기가 있고, 실제 회사 로고·인물 사진·개인정보가 없다.

## 10. 확장

- **새 아키타입**: 기존 블록을 조합한다. 예: 좌측 헤드라인 + 우측 폰 프레임(흰 카드 radius 28, 세로 260×520) / 가격표 = `.tbl` 3열 + 추천 열 `.hc` / 로드맵 = 가로 헤어라인 + `.chip` 분기 표시.
- **목업**: 실제 스크린샷 대신 `.card` + `.crow` + `.ph`로 그린다. 브라우저 프레임이 필요하면 흰 카드 상단에 28px 바와 회색 점 3개만.
- **여러 문서 일관성**: 데이터(JSON)와 템플릿 함수로 생성기를 만들면 장 수가 늘어도 글로우 위치·톤이 흔들리지 않는다.
