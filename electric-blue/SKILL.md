# Electric Blue Design System

블루 빛으로 채운 무대(stage) 위에 블랙 패널을 얹고, 그 안을 와이드 대문자 제목·큰 숫자·선 아이콘 카드로 구성하는 AI·테크 피치덱 스타일입니다. **빛은 무대이지 장식이 아닙니다.** 글로우는 정해진 4가지를 정해진 자리에만 쓰고, 나머지는 블랙·화이트·여백으로 정리합니다.

## 0. 작업 순서 (반드시 이 순서)

1. 포맷을 고르고, 템플릿 HTML과 `assets/electric-blue.css`를 **같은 결과물 폴더**에 복사한 뒤 `<link href="../assets/electric-blue.css">`를 `href="electric-blue.css"`로 바꾼다.
   - 슬라이드 덱(16:9, 1280×720): `templates/deck.html`에서 시작
   - 세로 롱페이지(웹뷰·한 장 PDF·모바일 공유): `templates/doc.html`에서 시작
2. 내용을 슬라이드/섹션 단위로 나눈다. **1장 1메시지**로, §5 아키타입 중 하나에 배정한다.
3. 각 장의 **광원**을 먼저 정한다(헤이즈 / 빔 / 없음 중 하나, §1-2). 그다음 템플릿 블록을 복제해 텍스트만 바꾼다.
4. 코일이 필요하면 템플릿 안의 `<svg class="coil">`를 그대로 쓰거나 `python3 scripts/coil.py [turns] [id] [spin]`으로 새로 만들어 `.coilwrap` 안에 붙인다.
5. `python3 scripts/render.py <file.html> [out_dir]`로 렌더한다.
6. **반드시 PNG를 열어서 직접 본다.** 덱은 `_check_<name>/sheet.png`와 `sNN.png`, 문서는 `full.png`. §9 체크리스트로 검수하고 고친 뒤 다시 렌더한다. 글로우를 바꿨다면 PDF도 `pdftoppm -r 50 -png out.pdf p`로 래스터화해 화면과 같은지 본다.

## 1. 원칙 6가지

1. **무대 + 블랙 패널.** 모든 장은 `.slide.stage`(블루 그라데이션 무대) 위에 블랙 패널 `.p`(#05060A)를 얹는다. 덱은 inset 14px, radius 10, 1px `--edge` 테두리이고, 문서는 패널 간격 14px로 쌓아 틈으로 무대가 보이게 한다. 패널은 **항상 블랙**이다. 라이트 패널은 없다.
2. **광원은 한 장에 하나.** 헤이즈(`.haze`)나 빔(`.beam`) 중 **하나만** 켠다. 둘 다 없어도 된다(Color 장처럼). 코일은 광원이 아니라 오브젝트이므로 표지·마무리에서만 헤이즈와 함께 쓸 수 있다.
3. **블루는 세 군데에만.** ① 솔리드 블루 카드 `.card.cv` 슬라이드당 최대 1장 ② 블루 텍스트 `.v` 한 구절(헤드라인 강조 또는 대표 숫자 1개) ③ 화이트 카드 안 1px 구분선 `.rule`. 이 외의 블루는 무대·글로우뿐이다.
4. **영문 대문자 디스플레이 + 한글 본문.** 영문 제목은 `.disp`(Montserrat 600, uppercase, 자간 +0.005em, 행간 1.04)로 2~4단어 2줄. **한글 헤드라인은 대문자 개념이 없으므로** `.hk`(Pretendard 700, 자간 −0.035em, 행간 1.2)로 쓰고, 영문 대문자 제목과 섞지 않는다. 한 장의 제목은 영문 `.disp` 또는 한글 `.hk` 중 하나로 정하고, 다른 하나는 서브 카피로 내린다.
5. **숫자가 주인공.** 지표는 `.num`(Montserrat 500)을 크게 쓰고 단위는 숫자의 약 60%(`45<span style="font-size:58px">%</span>`), 영문 단위는 약 45%(`4<span style="font-size:20px">weeks</span>`). 블루 숫자는 한 장에 1개다.
6. **카드는 4요소.** 아이콘 카드 구성은 항상 "좌상단 선 아이콘 → (빈 공간) → 문장 `.stmt` → 1px `.rule` → 굵은 라벨 `.lab`"이다. 내용은 위아래로 붙이고(`.card.flex`), 가운데는 비워 둔다.

### 1-2. 글로우 규칙 (이 디자인의 핵심)

| 요소 | 클래스 | 위치 | 강도 | 한도 |
|---|---|---|---|---|
| 무대 | `.stage` | 패널 바깥 전체 | 고정(토큰) | 모든 장 |
| 헤이즈 | `.haze.bl` `.br` `.tr` `.top` `.floor` | 패널의 **한 모서리 또는 한 변**에서 안쪽으로 | 중심 α .55~.95, 50~70%에서 0 | 슬라이드당 1개. 텍스트 블록 중심에 두지 않는다. 약하게 하려면 `style="opacity:.6"` |
| 빔 | `.beam` | 수평 1줄, 콘텐츠 블록 **사이**(제목과 타임라인 사이 등) | 코어 2px(블루→흰색), 헤일로 높이 90px | 슬라이드당 1개, Divider·Roadmap 장 전용. 헤이즈와 동시 사용 금지 |
| 글로우 점 | `.gdot` | 차트 데이터 포인트, 빔 위 타임라인 노드 | 30px 방사형 | 차트당 2~4개 |
| 코일 | `.coilwrap > svg.coil` | 패널 가장자리로 **블리드**(잘려 나가게) | — | 덱당 최대 2회(표지·마무리), 문서 1회(Hero). 텍스트 뒤로 들어가지 않게 |
| 오브 | `.orbs` | 영문 디스플레이 첫 줄 앞 | — | 덱 전체에서 1~2회 |

- **전부 gradient로 만든다.** `filter:blur()`, `backdrop-filter`, `text-shadow`, 큰 `box-shadow` 글로우는 쓰지 않는다(PDF에서 빠지거나 뭉개진다). 새 글로우가 필요하면 `radial-gradient(closest-side, rgba(31,77,255,.78), rgba(31,77,255,.32) 45%, transparent)` 패턴을 복제한다.
- 차트 선의 빛은 같은 path를 3겹(12px α.16 / 5px α.35 / 1.6px 그라데이션)으로 겹쳐 만든다.
- 글자는 절대 빛나지 않는다. 글로우는 면과 선에만 준다.

## 3. 타이포 스케일

폰트는 Pretendard(한글·본문)와 Montserrat(영문 디스플레이·숫자·라벨) 두 가지다. `<head>`에 두 링크를 반드시 넣는다(템플릿 참고). Montserrat는 원본 레퍼런스의 유료 와이드 지오메트릭 산세리프(Gilroy·Mont 계열)를 대신하는 무료 서체다. 한글은 `word-break:keep-all`.

| 역할 | 덱(1280) | 문서(900) | 클래스 |
|---|---|---|---|
| 표지 디스플레이 | 76–104px | 56px | `.disp` |
| 구분장·Thank you | 88–112px | 64px | `.disp` |
| 섹션 디스플레이 | 54–60px | 40px | `.disp` |
| 한글 헤드라인 | 38–42px / 700 / −0.035em | 30px | `.hk` (강조 `.v`) |
| 파트 번호 | 132px / 400 | — | `.num` |
| 대형 숫자 | 44–96px / 500 | 44–64px | `.num` |
| 카드 문장 | 15px / 400 | 14px | `.stmt` |
| 카드 라벨 | 14.5px / 600 | 13.5px | `.lab` |
| 본문/서브 | 15px | 14.5px | `.sub` |
| 캡션 | 12.5px | 12.5px | `.cap` |
| 라벨 | 11px Montserrat 600 · 대문자 · 자간 .16em | 동일 | `.lb` |
| 워드마크 | 12px 600 · 대문자 · 자간 .2em | 동일 | `.wm` |

- 대문자 변환(`text-transform:uppercase`)과 양수 자간은 **영문에만** 걸린다. 한글이 섞인 라벨(`Contact · 담당자`)은 괜찮지만, 한글 헤드라인에 `.disp`를 씌우지 않는다.
- 한글 헤드라인 크기는 같은 장 영문 디스플레이의 약 0.7배다(54px 영문 ↔ 38px 한글). 한글 제목에 이탤릭·800 이상 굵기는 쓰지 않는다.

## 4. 컴포넌트

- **카드 `.card`**: radius 16(문서 14), padding 22/24. `.w` 화이트(구분선 블루), `.cv` 솔리드 블루(구분선 흰색 55%, 슬라이드당 1장), `.k` 다크(1px hair 테두리), `.k.on` 다크 + 블루 테두리(비교표의 추천안). 2×2 그리드에서는 **좌상단 1장만** `.cv`로 둔다.
- **지표 카드**: `.card.k`에 `background:var(--ink)`를 주고 `.haze.floor` 위에 올린다. 3장을 서로 다른 높이(top 318/366/390)로 엇갈려 놓고 하단은 패널 밖으로 블리드시킨다. 숫자 → `.cap` → 짧은 `.rule`(120px).
- **선 아이콘 `.ico`**: 칩 없이 44px(`.sm` 28px), 선 1.4px 고정. `assets/icons.md` 세트를 쓰고 카드당 1개만 둔다.
- **필 `.pill` / 태그 `.tag`**: 필은 아웃라인 캡슐(`.on`은 블루 테두리 + `.dot`), 한 줄 2~3개. 태그는 차트 데이터 포인트 아래 라벨("도입 전")에만 쓰는 radius 6 사각 라벨.
- **곡선 차트 `.chart`**: SVG(덱 520×250, 문서 372×240)를 viewBox와 같은 px 크기로 놓고, 숫자 라벨·태그·`.gdot`은 같은 좌표로 HTML 절대배치한다. 하강/상승 S곡선 1개, 데이터 포인트 2~3개, 수직 드롭라인과 바닥 기준선은 1px α.16~.18. 축 눈금·격자·범례는 그리지 않는다. 곡선은 패널 왼쪽 밖에서 들어오게(`M-56 …`) 시작한다.
- **타임라인 `.tl`**: 빔 바로 아래 4열. 각 열은 1px 세로선(아래로 갈수록 사라짐) + 연도 `.yr` + 제목 `h4` + 하단 `.cap`. 빔과 세로선이 만나는 지점에 `.gdot`.
- **헤어라인 행 `.rows`**: 목차·비교표·메타 정보. 자식 div마다 `grid-template-columns`를 직접 지정한다. 세로선·격자·지브라 금지.
- **막대 `.bar`**: 6px 캡슐, 채움은 `--volt → --ice`. 보조 지표에만.
- **헤더/푸터(덱)**: 헤더 좌측은 항상 워드마크(`.wm`, 프로젝트명 대문자), 우측은 `.lb`.

  | 장 유형 | 헤더 우측 | 푸터 `.ft` |
  |---|---|---|
  | Cover | 문서 종류 · 날짜 | 없음(하단 메타 `.rows`) |
  | Contents · 본문 장 | `01 Why · NN / TT` (목차는 `NN / TT`) | 좌측 `.cap` 각주 · 우측 `.lb` 문서 종류 · 연도 |
  | Divider · Metrics · Closing | `NN / TT` | 없음 |

## 5. 아키타입 (템플릿에 전부 있음)

**덱 `templates/deck.html`**
1. **Cover** — 헤이즈 `bl` + 코일(우측, `spin -40`, 하단 블리드). 좌측 `.lb` → `.orbs` + 디스플레이 2줄 → 한글 제목 24px/600 → `.sub` 한 줄, 하단 메타 `.rows` 3칸.
2. **Contents** — 헤이즈 `tr`. 좌측 디스플레이 60px("What’s Inside"), 우측 `.rows` 목차(번호 / 제목 / 캡션 / 페이지), 첫 번호만 `.v`.
3. **Divider** — 빔 1줄. 빔 위에 파트 번호 132px + `.pill`, 아래에 디스플레이 88px + 한 문장, 우하단 파트 내 목차.
4. **Results** — 광원 없음. 좌측 `.hk` + `.sub` + 하강 곡선 차트(100% → 30%), 우측 2×2 아이콘 카드(좌상단 1장 `.cv`).
5. **Metrics** — 헤이즈 `floor`. 영문 디스플레이 + 우측 서브, 하단 대형 숫자 카드 3장(엇갈린 높이, 블리드, 첫 숫자만 `.v`).
6. **Roadmap** — 빔 1줄. `.hk` + `.sub`, 빔 아래 4열 `.tl`과 `.gdot` 노드 4개.
7. **Compare** — 헤이즈 `tr`(opacity .7). 좌측 340px `.hk`, 우측 라벨 열 + Before 행 + After `.card.k.on`. 행 높이 62px 통일.
8. **Closing** — 코일(우하단 블리드). "Thank You" 112px, 한 문장, 하단 연락 `.card.k` + 다음 단계 `.card.cv`.

**문서 `templates/doc.html`**: Hero(헤이즈 + 코일 + 스탯 3장) → Results(곡선 + 2×2) → Roadmap(빔 + 4열) → Metrics(헤이즈 floor + 엇갈린 숫자 카드) → Compare(헤어라인 표) → Contact(Thank You + 연락·다음 단계). 각 패널 광원 1개 이하, 코일은 Hero에만.

## 6. 레이아웃 규칙

- **덱 좌표계**: 패널 안 콘텐츠 영역은 left/right 56px, top 92~100px, bottom 64~68px. 헤더 top 34, 푸터 bottom 28. 복잡한 장은 `position:absolute`로 블록을 고정 배치한다(템플릿 방식). 텍스트·카드에는 `.z`(z-index 3)를 줘서 헤이즈·빔 위에 올린다.
- **문서**: 패널 padding 44, 콘텐츠 폭 780px(900 − 16×2 − 44×2). 열 좌표를 계산할 때 이 값을 쓴다.
- **간격**: 카드 사이 10~14px, 블록 사이 24~34px.
- **비대칭 분할**: 좌측 340~560px 정보 열 + 우측 가변. 2×2 그리드는 우측 절반에. 같은 카드 4장 이상 균등 나열은 타임라인·문서 스탯 줄에만.
- **블리드**: 코일과 지표 카드는 패널 가장자리 밖으로 잘려 나가게 둔다. 잘리지 않고 패널 한가운데 떠 있으면 클립아트처럼 보인다.
- **줄바꿈은 직접 정한다**: 제목·카드 문장은 `<br>`로 의미 단위에서 끊는다. 숫자·시간·필에는 `white-space:nowrap`.

## 7. 카피 규칙

- 헤드라인은 결과·변화를 말하는 **단정형**으로 쓴다. 예: "측정 가능한 결과, **첫 달부터** 보입니다", "같은 일, **다른 속도**". 강조 `.v`는 한 구절만.
- 영문 디스플레이는 2~4단어 명령형·대구형(`Automate the Routine`, `Less Routine, More Focus`, `Why Automate Now`). 문장형 영어 본문은 쓰지 않는다.
- 카드 문장은 "대상 + 변화" 2줄 13자 내외(`월말 보고서 작성이 / 20배 빨라졌습니다`), 라벨은 부서·영역 명사(`재무팀`).
- 숫자를 앞에 세운다(`24/7`, `45%`, `−70%`). 출처·기준은 `.cap` 각주로 밝힌다(“수치는 예시 · 파일럿 4주 평균”).
- "혁신적인", "차세대", "업계 최고" 같은 근거 없는 최상급은 쓰지 않는다.

## 8. 금지 사항 (싸 보이는 글로우 · 생성형 티)

- 네온 글자, `text-shadow`, 글자 테두리 발광, 글자 그라데이션
- 빔 2줄 이상, 헤이즈 + 빔 동시, 헤이즈를 텍스트 정중앙에, 코일 3회 이상
- `filter:blur` · `backdrop-filter` · 글래스모피즘(반투명 유리 카드) · 큰 `box-shadow` 글로우
- 팔레트 외 색(보라·시안·민트·마젠타), 다색·무지개 그라데이션, 블루 카드 2장 이상
- 라이트(흰) 패널 배경, 패널 없이 무대 위에 바로 글자
- 이모지, 컬러·채움 아이콘, 아이콘 칩 배경, 스톡 3D 이미지, 실제 로고
- 한글에 uppercase·양수 자간·와이드 폰트 흉내, 영문 디스플레이 5단어 이상
- 차트 격자·축 눈금·범례, 표 세로선, 카드 안의 카드
- 가운데 정렬 본문 단락, 불릿 5개 이상, 긴 설명 문장으로 카드 채우기

## 9. 검수 체크리스트 (렌더 PNG를 보면서)

- [ ] 장마다 광원이 1개 이하다(헤이즈 또는 빔). 코일은 표지·마무리뿐이다.
- [ ] 블루 카드 1장, 블루 숫자/구절 1개 이하다.
- [ ] 텍스트가 코일·헤이즈 중심과 겹치지 않고, 코일 꼬리(튜브 끝)가 패널 밖으로 잘려 있다.
- [ ] 텍스트가 카드·패널 밖으로 넘치거나 겹치지 않는다. 특히 긴 영문 디스플레이, 비교표 마지막 행, 타임라인 하단 캡션과 푸터.
- [ ] 한글이 어절 중간에서 끊기지 않고, 숫자·필이 두 줄로 갈라지지 않는다.
- [ ] 차트 라벨·태그·글로우 점이 곡선 좌표와 정확히 맞는다.
- [ ] Montserrat가 로드됐다(대문자 제목이 기본 산세리프로 보이면 링크·네트워크 확인).
- [ ] PDF를 래스터화해 봐도 헤이즈·빔·코일이 화면과 같다.
- [ ] 페이지 번호 `NN / 총장수`, 목차 페이지가 실제와 맞는다. 의뢰처가 원치 않는 로고·개인정보가 없다.

## 10. 확장

- **코일 변형**: `python3 scripts/coil.py 9 d` (감은 수 9, id 접두사 d), `python3 scripts/coil.py 11 c -40` (화면 −40° 회전, 꼬리가 아래로). 한 HTML에 모양이 다른 코일을 넣을 때는 id 접두사를 다르게 준다. 크기는 `.coilwrap`의 width로만 조절한다.
- **새 아키타입**: 기존 블록을 조합한다. 예: Divider의 빔 + Results의 2×2 카드 → "4대 기능" 장 / Metrics 카드 3장 + Compare 표 → "가격·플랜" 장(추천 플랜만 `.card.k.on`).
- **목업**: 제품 화면이 필요하면 스크린샷 대신 `.card.k` 안에 HTML로 그린 간단한 앱 프레임(상단 바 + 행 몇 줄)을 두고, 강조 행 하나만 `--volt` 1px 테두리를 준다.
- **여러 문서 일관성**: 데이터(dict/JSON)와 템플릿 함수로 생성기를 만들면 장 수가 늘어도 광원·블루 한도 규칙이 흔들리지 않는다.
