# Violet Grid Design System

페이지 전체를 한 색(바이올렛 · 화이트/그레이 · 블랙)으로 칠하고, 12열 그리드 위에 **거대한 대문자 제목 하나**와 **작은 에디토리얼 노트**를 대비시키는 브랜드북 스타일입니다. 라운드 패널이 아니라 각진 풀블리드 페이지, 장식이 아니라 **스케일 대비 · 그리드 · 러닝 푸터**로 완성도를 만듭니다.

## 0. 작업 순서 (반드시 이 순서)

1. 포맷을 고르고, 템플릿 HTML과 `assets/violet-grid.css`를 **같은 결과물 폴더**에 복사한 뒤 `<link href="../assets/violet-grid.css">`를 `href="violet-grid.css"`로 바꾼다.
   - 슬라이드 덱(16:9, 1280×720): `templates/deck.html`에서 시작
   - 세로 롱페이지(웹뷰·한 장 PDF·모바일 공유): `templates/doc.html`에서 시작
2. 내용을 슬라이드/섹션 단위로 나눈다. **1장 1메시지**로, §5 아키타입 중 하나에 배정하고 페이지 색을 정한다(§1-2).
3. 템플릿 블록을 복제해 텍스트만 바꾼다. 배치는 `.at`(`--c` 시작열, `--s` 칸수)로 12열에 붙인다. 새 레이아웃을 즉흥으로 만들기 전에 기존 아키타입을 먼저 쓴다.
4. 아이콘이 필요하면 `assets/icons.md`의 path를 `<svg class="ic" viewBox="0 0 24 24">…</svg>`로 넣는다.
5. `python3 scripts/render.py <file.html> [out_dir]`로 렌더한다.
6. **반드시 PNG를 열어서 직접 본다.** 덱은 `_check_<name>/sheet.png`와 개별 `sNN.png`, 문서는 `full.png`. §9 체크리스트로 검수하고 넘침·겹침·줄바꿈 깨짐을 고친 뒤 다시 렌더한다.

## 1. 원칙 6가지

1. **각진 풀블리드 페이지.** 페이지(`.pg.v` 바이올렛 / `.pg.w` 화이트 / `.pg.g` 라이트그레이 / `.pg.k` 블랙)는 모서리 없이 화면 전체를 칠한다. 라운드는 페이지 위에 얹는 작은 오브젝트(카드 14px, 칩·태그·프로필 캡슐)에만 쓴다.
2. **페이지 색을 돌린다.** 바이올렛 → 화이트 → 블랙 → 바이올렛 → 그레이 …처럼 바꾼다. 같은 색을 2장 넘게 연속으로 두지 않는다. 바이올렛은 표지·스테이트먼트·마무리, 블랙은 구분장·서비스, 화이트/그레이는 목차·지표·일정에 쓴다.
3. **스케일 대비.** 한 장에 거대한 것은 하나만 있다: 대문자 디스플레이(120–212px) **또는** 한글 헤드라인(30–48px) **또는** 대형 숫자. 나머지는 12px 노트와 10.5px 라벨로 아주 작게 둔다. 중간 크기를 늘어놓지 않는다.
4. **좌상단 에디토리얼 노트.** 모든 장의 좌상단(1–3열)에 `.side` = 대문자 라벨(`01 — Metrics`) + 2~3줄 한글 노트를 둔다. 본문 블록은 4열 또는 7열에서 시작한다.
5. **강조 글자 스왑.** 대문자 제목에서 한 단어 안의 1~2글자만 `<em>`으로 감싸 **바이올렛 이탤릭**으로 바꾼다(바이올렛 페이지에서는 흰색). 한 제목에 최대 2곳. 한글 제목은 이탤릭 없이 한 구절만 `<b>`로 색만 바꾼다.
6. **러닝 푸터는 모든 장에.** `.rf` = 상단 헤어라인 + 4칸(워드마크 · 문서명 · 섹션 · `NN / TT`). 표지와 마무리도 예외 없다.

## 2. 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--violet` | #8b6cf0 | 메인 페이지 색, 강조 글자, 목차·단계 번호, 차트 1순위 |
| `--v2` / `--v3` | #a891f4 / #c6b8f8 | 차트 틴트 2·3, 블랙 위 강조 텍스트(`--v2`) |
| `--lav` | #e4ddfc | 라벤더 카드·칩·태그 채움, 차트 틴트 4 |
| `--white` / `--gray` | #fff / #e9e9e9 | 화이트·그레이 페이지, 흰 카드 |
| `--black` / `--tile` | #0a0a0a / #1b1b1b | 블랙 페이지·카드 / 블랙 위 한 단계 밝은 면 |
| `--ink` / `--sub` | #0a0a0a / #6f6f6f | 본문 / 캡션 |
| `--hair` / `--hairW` | rgba(0,0,0,.18) / rgba(255,255,255,.22) | 1px 헤어라인 |
| `--m` / `--gut` | 40px / 16px | 덱 바깥 여백 / 12열 거터 |

**이 팔레트 외의 색은 쓰지 않는다.** 그라데이션은 어디에도 없다. 차트는 `--violet → --v2 → --v3 → --lav` 4단 틴트만 쓰고, 가장 중요한 막대 하나만 `--violet`(`.vbars i.a`)으로 칠한다. 브랜드 색을 쓰려면 `--violet`, `--v2`, `--v3`, `--lav` 네 값만 같은 계열로 바꾼다.

## 3. 타이포 스케일

폰트는 **Inter Tight**(영문 디스플레이·숫자·라벨, 원본 Suisse Intl의 무료 대체)와 **Pretendard**(한글 전부) 두 가지다. Inter Tight는 이탤릭까지 불러와야 강조 글자가 진짜 이탤릭으로 나온다(템플릿 `<head>` 링크 그대로 사용). 한글은 `word-break:keep-all`.

| 역할 | 덱(1280) | 문서(900) | 클래스 |
|---|---|---|---|
| 표지 디스플레이 | 150–212px / 500 / -0.05em / 행간 .86 | 110–120px | `.dsp` (강조 `em`) |
| 구분장·마무리 디스플레이 | 130–150px | 92–120px | `.dsp` |
| 목차 항목 · 번호 | 70–84px | 56px | `.toc .t` / `.toc .n` |
| 한글 헤드라인 | 30–48px / 600 / -0.06em | 30–36px | `.kd` (강조 `b`) |
| 스테이트먼트(문단형) | 44–52px / 500 / 행간 1.14 | 30–34px | `.st` (강조 `b`) |
| 대형 숫자 | 54–96px / 500 | 44–58px | `.num` |
| 단계 제목 | 19–21px / 600 | 19px | `.kd` inline |
| 노트(에디토리얼 본문) | 12px / 1.55 | 12px | `.note` (`.cols2` 2단) |
| 캡션 | 11.5px | 11.5px | `.cap` |
| 라벨 | 10.5px / 600 / 대문자 / +0.06em | 동일 | `.lbl` |
| 러닝 푸터 | 10px / 500 / 대문자 | 동일 | `.rf` |

**한글 제목 조판 규칙**
- 한글은 대문자가 없으므로 영문 디스플레이 크기의 **약 0.7배**로 줄이고(영문 150px ↔ 한글 40–48px 헤드라인, 또는 표지 보조 제목 30px), weight 600, 자간 -0.06em, 행간 1.04로 꽉 묶는다.
- 한글을 `.dsp`(대문자·Inter Tight)에 넣지 않는다. 한글이 거대 제목 자리에 와야 하면 `.kd`를 80–110px까지 키우되 한 줄 8자 이내로 끊는다.
- 한글에는 이탤릭·기울임을 절대 쓰지 않는다(Pretendard에 이탤릭이 없어 가짜 기울임이 된다). 강조는 `<b>` 색 변경만.
- 영문 대문자 제목 + 한글 헤드라인을 한 장에 같이 쓸 때는 영문이 크기, 한글이 의미를 맡는다. 영문은 하단, 한글은 상단 7열(또는 영문 바로 아래 1열)에 둔다.
- 숫자 안 한글 단위(억·명·원)는 `<span style="font-family:Pretendard;font-weight:600">억</span>`처럼 따로 감싸고 숫자의 45% 크기로.

## 4. 컴포넌트

- **사이드 노트 `.side`**: 좌상단(left 40, top 34, 폭 2열=203px, `.w3`는 3열). `.lbl` 한 줄 + `.note` 2~3줄. 모든 장에 1개.
- **러닝 푸터 `.rf`**: 12열 그리드로 4칸을 1–3 · 4–6 · 7–9 · 10–12열에 고정. 상단 1px 헤어라인. 마무리처럼 오른쪽이 타일로 덮이면 `right`를 줄이고 6열로 축소(템플릿 08 참고).
- **목차 `.toc`**: 행마다 `1fr 150px 90px` = 대문자 항목 · 한글 캡션 · 바이올렛 페이지 번호(우측 정렬). 행 사이 헤어라인 없이 행간 .92로 빽빽하게 쌓는다. 6~7개까지.
- **스탯 카드 `.card`**: radius 14, padding 18/20, 세로 flex. 구성은 "상단 `.hd`(라벨 좌 · 칩이나 캡션 우) → 큰 `.num` → `.cap` → 하단 차트(`margin-top:auto`)". 종류는 `.w` 흰 · `.k` 블랙 · `.v` 바이올렛 · `.l` 라벤더 · `.t` 블랙 위 타일. 3개를 나란히 둘 때 가운데 하나만 `.k`로 더 크게(높이 400 vs 300, `align-items:end`).
- **칩 `.chip`**: 30px 캡슐 수치·속성(`+35.5%`, `12 Weeks`). 기본 라벤더, `.v` 바이올렛, `.k` 블랙. 한 줄 2~3개.
- **태그 `.tag`**: 26px 아웃라인 대문자 캡슐(업종·카테고리·기간). `.f` 라벤더 채움은 한 줄에 1개, `.fk` 블랙 채움.
- **프로필 필 `.prof`**: 흰 큰 캡슐 + 64px 원형 아바타(`.av`, 이니셜 = 사진 자리) + 이름·역할(`.nm`) + 회색 한 줄(`.ds`). 바이올렛·라벤더 위에 세로로 2~3개 쌓는다.
- **차트**: `.vbars`(세로 막대, `<i style="height:%">`, 클래스 `a`·`b`·기본·`d`로 틴트 지정)와 `.area`(인라인 SVG 영역 차트: `.f` 채움 + `.s` 선 + `.gl` 가이드라인 2개). 축·눈금·범례는 생략하고 큰 숫자가 해석을 맡는다. `.hbar`는 가로 비율 막대.
- **헤어라인 행 `.rows`**: 일정·스펙·Do/Don't. 행마다 `grid-template-columns`를 직접 지정. 번호는 `.num.vt`(바이올렛), 기간은 `.tag`.
- **아이콘 그리드 `.icg`**: 블랙 페이지 위 6열, 30px 흰 선 아이콘 + 아래 `.cap`. 칩이나 원으로 감싸지 않는다.
- **워드마크 타일 `.wt`**: 각진 색면(`.k` 블랙 · `.l` 라벤더(글자 바이올렛) · `.w` 흰 · `.v` 바이올렛) 가운데 `.wm` 워드마크. 2×2 또는 1×3으로 붙여 쌓고 틈을 두지 않는다. 좌상단에 `.lbl`로 "On Black" 같은 설명을 붙일 수 있다.
- **이미지 자리 `.ph`**: 사진·3D·목업 대신 라벤더(블랙 위는 `--tile`) 면 + 안쪽 점선 + "이미지 자리" 텍스트. 외부 이미지는 넣지 않는다.

## 5. 아키타입 (템플릿에 전부 있음)

**덱 `templates/deck.html`**
1. **Cover**(바이올렛): 좌상단 노트, 7열·10열에 메타(Prepared for / Vol·날짜), 하단에 12열 폭 대문자 제목 2줄(156px, 강조 글자 1곳), 그 아래 한글 제목 30px와 우측 칩 2개.
2. **Contents**(화이트): 좌상단 노트, 4–12열에 `.toc` 6행(82px).
3. **Divider**(블랙): 7–12열 상단에 한글 헤드라인 40px(강조 `--v2`), 하단 12열 대문자 제목 150px(강조 2곳).
4. **Statement**(바이올렛): 4–12열 상단 문단형 한글 50px(강조 구절은 흰색), 하단 4·7·10열 시작 3칸 노트(각 상단 헤어라인).
5. **Metrics**(그레이): 4열 한글 헤드라인, 4–12열에 카드 3개(흰 · 블랙 크게 · 흰), 좌하단 1–3열 대형 숫자(측정 기간).
6. **Roadmap**(화이트): 좌하단 1–6열 대문자 제목 132px, 우측 7–12열 `.rows` 4단계(바이올렛 번호 · 단계 제목 · 노트 · 기간 태그, 진행 중 단계만 `.tag.f`).
7. **Services**(블랙): 4열 한글 헤드라인 2줄, 4–12열 `.icg` 6×2, 하단 업종 태그 한 줄(1개만 `.f`).
8. **Closing**(바이올렛 + 타일): 좌측 대문자 "Let’s Grow" 138px + 프로필 필 2개, 우측 절반 워드마크 타일 2×2(블랙 · 라벤더 · 흰 · 바이올렛).

**문서 `templates/doc.html`**: Hero(바이올렛, 메타 3칸 + 118px 제목 + 한글 제목 + 칩) → Overview(화이트, 스테이트먼트 + 3칸 노트) → Metrics(그레이, 카드 3개) → Services(블랙, 아이콘 그리드 + 태그) → Roadmap(화이트, 92px 제목 + 단계 행) → Contact(바이올렛, 제목 + 프로필 필 2개 + 워드마크 타일 1×3). 섹션마다 끝에 `.rf`.

## 6. 레이아웃 규칙

- **덱 그리드**: 1280 폭, 바깥 여백 40, 12열, 거터 16(열 폭 약 85px). 열 시작 x = 40 + (n-1)×101.3. 모든 블록은 `.at`으로 열에 붙인다. `style="--c:4;--s:9;top:120px"`.
- **세로 기준선**: 상단 요소는 top 34, 러닝 푸터는 bottom 20(헤어라인 y≈690). 대문자 제목은 화면 아래쪽 절반(top 300~380)에 두고 위쪽은 작은 글자로 비워 둔다. 하단 제목과 푸터 사이 최소 40px.
- **문서 그리드**: 섹션 padding 36/36/30, 내부 `.grid`(12열, 거터 14) + `grid-column`. 노트 `1/4`, 본문 `4/13`. 섹션끼리 틈 없이 붙인다.
- **비대칭**: 좌측 1–3열은 노트 전용 여백, 본문은 4열 또는 7열 시작. 같은 크기 카드를 4개 이상 균등 나열하지 않는다(아이콘 그리드만 예외).
- **줄바꿈은 직접 정한다**: 대문자 제목·한글 헤드라인은 `<br>`로 의미 단위에서 끊는다. 대문자 제목 한 줄은 1200px(덱) / 828px(문서)을 넘지 않게 글자 수로 크기를 정한다(Inter Tight 500 대문자 ≈ 글자당 0.62em). 짧은 값에는 `white-space:nowrap`.

## 7. 카피 규칙

- 대문자 제목은 **영문 2~4단어**의 짧은 슬로건형("Grow Faster, Stay Longer", "Scale Users, Not Costs"). 의미는 한글 헤드라인이 전달한다.
- 한글 헤드라인은 대비 구조로, 강조는 한 구절: "광고비가 아니라 **남는 사용자**를 키웁니다".
- 노트는 2~3줄의 완결된 문장으로 쓴다. 불릿 대신 문장.
- 라벨은 영문 대문자 + 번호: `01 — Overview`, `New Installs`, `Prepared for`.
- 숫자를 앞에 세운다(`23.45%`, `48.2K`, `+35.5%`). 소수점은 마침표로.
- 근거가 불분명한 최상급("업계 최고", "국내 유일")은 쓰지 않는다. 예시 수치에는 노트에 "예시"라고 밝힌다.

## 8. 금지 사항 (생성형 티가 나는 것)

- 라운드 페이지·패널, 카드 안의 카드, 그림자(`box-shadow`), 글래스모피즘
- 배경 그라데이션, 그라데이션 막대, 글로우, 네온
- 팔레트 외 색(초록·주황·파랑 등), 무지개 차트, 한 화면에 바이올렛 강조가 5곳 이상
- 강조 글자를 단어 전체·여러 단어에 적용, 한글 이탤릭·가짜 기울임
- 대문자 제목을 한글로 쓰거나 한 장에 거대 제목 2개
- 가운데 정렬 본문, 긴 불릿 리스트(4개 초과)
- 3D 오브젝트, 스톡 사진, 이모지, 컬러 아이콘, 외부 이미지
- 러닝 푸터 누락, 노트 없이 제목만 있는 장

## 9. 검수 체크리스트 (렌더 PNG를 보면서)

- [ ] 대문자 제목이 오른쪽 여백(40px)을 넘거나 푸터 헤어라인과 겹치지 않는다.
- [ ] 강조 글자(`em`)가 진짜 이탤릭으로 나온다(이탤릭 폰트 로드 확인). 제목당 2곳 이하.
- [ ] 한글이 어절 중간에서 끊기지 않고, 숫자·기간 태그가 두 줄로 갈라지지 않는다.
- [ ] 모든 장에 좌상단 `.side`와 하단 `.rf`가 있고 `NN / TT`와 목차 번호가 실제와 맞다.
- [ ] 페이지 색이 같은 색 3장 연속이 아니다.
- [ ] 블록 왼쪽 끝이 1·4·7·10열 중 하나에 맞는다(눈으로 세로선 정렬 확인).
- [ ] Inter Tight·Pretendard가 로드됐다(대문자가 기본 산세리프로 보이면 링크 확인).
- [ ] 예시 브랜드명·연락처가 실제 의뢰 정보로 바뀌었고, 원치 않는 개인정보가 없다.

## 10. 확장

- **새 아키타입**: 기존 블록을 조합한다. 예: 바이올렛 페이지 + 4–12열 `.toc` 대신 `.rows` 가격표 / 블랙 페이지 + `.ph` 목업 + 우측 노트 / 그레이 페이지 + 카드 2×2.
- **목업**: 앱 화면은 `.ph`나 HTML로 그린 단순 폰 프레임(블랙 라운드 사각 + 내부 카드)으로 대신한다.
- **여러 문서 일관성**: 데이터(dict/JSON)와 템플릿 함수로 생성기를 만들면 장수가 많아도 그리드와 푸터가 흔들리지 않는다.
