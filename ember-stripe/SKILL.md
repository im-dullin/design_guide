# Ember Stripe Design System

순수 블랙 무대 위에 따뜻한 엠버 빛 하나를 비추는 런치 덱 스타일입니다. 표지에서는 빛이 세로 골유리를 통과해 줄무늬로 갈라지고, 본문 장에서는 모서리에 은은한 글로만 남깁니다. 고급스러움은 **어둠의 면적, 얇은 큰 글자, 빛의 절제**에서 나옵니다.

## 0. 작업 순서 (반드시 이 순서)

1. 포맷을 고르고, 템플릿 HTML과 `assets/ember.css`를 **같은 결과물 폴더**에 복사한 뒤 `<link href="../assets/ember.css">`를 `href="ember.css"`로 바꾼다.
   - 슬라이드 덱(16:9, 1280×720): `templates/deck.html`에서 시작
   - 세로 롱페이지(웹뷰·한 장 PDF·모바일 공유): `templates/doc.html`에서 시작
2. 내용을 슬라이드/섹션 단위로 나눈다. **1장 1메시지**로, §5 아키타입 중 하나에 배정한다. 이때 **빛 계획**을 같이 정한다: 골유리 장(최대 3장)과 본문 장마다 글로 위치(bl/br/tr/tl).
3. 템플릿 블록을 복제해 텍스트만 바꾼다. 새 레이아웃을 만들기 전에 기존 아키타입을 먼저 쓴다.
4. `python3 scripts/render.py <file.html> [out_dir]`로 렌더한다. out_dir은 결과물 폴더 밖 임시 폴더로 둔다.
5. **반드시 PNG를 열어서 직접 본다.** 덱은 `_check_<name>/sheet.png`와 개별 `sNN.png`, 문서는 `full.png`. §9 체크리스트로 검수하고 고친 뒤 다시 렌더한다. 빛이 PDF에도 남았는지 PDF 한 장을 열어 확인한다.

## 1. 원칙 5가지

1. **블랙이 무대.** 모든 배경은 `#000`이다. 회색 배경, 패널, 라이트 장은 없다. 면적의 70% 이상은 어둠으로 남긴다.
2. **빛은 두 종류, 한 장에 하나.**
   - **골유리 `.flute`** — Cover · Divider · Closing 전용, 덱 전체 최대 3장, 문서는 Hero · Closing 2곳.
   - **코너 글로 `.glow`** — 본문 장에 0~1개. 줄무늬 없이 모서리 하나에서만 번진다. 연속한 장은 위치를 바꿔 리듬을 만든다(bl → tr → br …).
   - 두 가지를 한 장에 같이 쓰지 않는다. 본문 장에 줄무늬를 넣지 않는다.
3. **얇고 크게.** 영문 디스플레이는 Inter 300, 한글 헤드라인은 Pretendard 300, 자간 -0.045em. 2줄로 끊어 좌측 정렬한다. 굵은 글자는 카드 제목(600)뿐이다.
4. **숫자는 카드 우상단.** 스탯 카드(`.card`)는 각진 모서리 #1c1c1c, 큰 숫자를 오른쪽 위에, 굵은 제목과 회색 설명을 아래에 붙인다. 카드는 반투명(α .78)이라 글로 위에 놓이면 빛이 살짝 비친다 — 이것이 의도다.
5. **엠버 텍스트는 한 구절.** 텍스트 강조(`.a`, 숫자 단위, 활성 단계)는 `--ember-hi` 한 곳만. 엠버로 면을 칠하거나 버튼을 만들지 않는다.

| `--line` | #2a2a2a | 막대 바탕 · 카드 안 구분 |
| `--hair` | rgba(255,255,255,.12) | 1px 헤어라인 |
| `--ink` | #ffffff | 디스플레이 · 숫자 · 카드 제목 |
| `--body` | #a3a3a3 | 리드 · 캡션 |
| `--sub` | #6e6e6e | 라벨 · 페이지 번호 |
| `--ember-deep` | #5a1e08 | 글로 가장자리 |
| `--ember` | #c4521a | 글로 본체 |
| `--ember-hi` | #e07a2c | 글로 코어 · 텍스트 강조 |
| `--ember-soft` | #f0a868 | 골 하이라이트(투명도 .09 이하로만) |

**유채색은 엠버 4단계뿐이다.** 브랜드 색으로 바꿀 때는 엠버 4개를 같은 명도 순서(어둠 → 본체 → 코어 → 하이라이트)로 한 계열에서 바꾸고 `ember.css`의 rgba 값(224,122,44 / 196,82,26 / 90,30,8)도 함께 바꾼다. 차가운 색으로 바꾸면 이 스타일의 따뜻함이 사라지므로 권하지 않는다.

### 빛 규칙 (시그니처)

| 항목 | 골유리 `.flute` | 코너 글로 `.glow` |
|---|---|---|
| 쓰는 장 | Cover(기본) · Divider(`.flute.pane` 우측 46%) · Closing(`.flute.low` 아래에서) | 본문 장 전부(선택) |
| 개수 | 덱 최대 3장 · 장당 1개 | 장당 최대 1개 · 문서 전체 2개 |
| 구조 | 골 음영 34px 주기 + 밝기 변조 212px · 460px 주기 2겹 + 엠버 radial 2개 + 좌측·하단 어둠 | 820×600 radial 1개, 줄무늬 없음 (`.sm` 560×420) |
| 세기 상한 | 코어 rgba(232,140,70,.95), 흰색·노랑까지 올리지 않는다 | 코어 알파 .62(아래 모서리) · .55(위 모서리) 이하 |
| 텍스트 영역 | 제목이 놓이는 좌측 40%·하단 20%는 어둠 그라데이션으로 거의 블랙 | 글로 위에 본문 단락을 올리지 않는다(카드·숫자·워드마크는 가능) |

- 빛은 **CSS 그라데이션만** 쓴다(repeating-linear-gradient + radial-gradient). `filter:blur`, `backdrop-filter`, `mix-blend-mode`, 이미지는 PDF에서 사라지거나 깨지므로 금지.
- `.flute`/`.glow`는 섹션의 첫 자식으로 두면 `z-index:-1`로 내용 아래에 깔린다(`.slide`/`.sec`가 `isolation:isolate`).
- 골 주기·각도·세기를 즉흥으로 바꾸지 않는다. 위치만 변형 클래스로 바꾼다.

## 3. 타이포 스케일

폰트는 Pretendard(한글)와 Inter(영문·숫자, opsz 축으로 큰 크기에서 디스플레이 컷) 두 가지다. `<head>`에 두 링크를 반드시 넣는다. 한글은 `word-break:keep-all`.

| 역할 | 덱(1280) | 문서(900) | 클래스 |
|---|---|---|---|
| 표지 디스플레이 | 104–132px / 300 | 84px | `.disp` |
| 구분장 · Thank you | 96–128px | 84px | `.disp` |
| 섹션 디스플레이(영문) | 64–72px | 56px | `.disp` |
| 한글 헤드라인 | 52px / 300 / -0.045em / 1.22 | 40px | `.h` (강조 `.a`) |
| 히어로 숫자 | 150–200px / 300 | 150px | `.num` |
| 카드 숫자 | 54–68px / 300, 우측 정렬 | 54px | `.card .num` |
| 카드 제목 | 18px / 600 | 16–17px | `.t` |
| 리드(우측 회색 단락) | 14–15px, 폭 250–340px | 14px | `.lead` |
| 캡션 · 카드 설명 | 13.5px | 13px | `.cap` |
| 라벨 · 페이지 번호 | 12.5px Inter 400 | 동일 | `.micro` · `.lbl` |
| 표지 캡션 | 15px Inter 400 | 동일 | `.kick` |
| 워드마크 | 13px Inter 500, 대문자 + `<sup>®</sup>` | 동일 | `.wm` |

- 디스플레이·헤드라인은 300보다 굵게 쓰지 않는다. 600은 카드 제목에만.
- 숫자 단위는 숫자의 45–50% 크기로 붙이고, 히어로 숫자 단위만 `--ember-hi`로 칠할 수 있다(`+31<span style="font-size:96px;color:var(--ember-hi)">%</span>`).
- `.num` 안에 한글을 넣지 않는다. "1 in 4", "5.9h"처럼 영문 단위를 쓰거나 한글 단위는 `<span style="font-family:Pretendard">`로 감싼다.

## 4. 컴포넌트

- **스탯 카드 `.card`**: 모서리 0, padding 26/26/28, 높이 240–270px. 순서는 우상단 `.num` → (빈 공간) → `.t` → `.cap` 2줄. 3개를 `.cards`(3열, gap 10px)로 나란히 둔다. 글로 위에 놓아 빛이 비치게 하는 게 기본이고, 차트처럼 읽기가 중요하면 `.card.solid`.
- **헤어라인 행 `.rows`**: 목차·기능 목록·스펙. 자식마다 `grid-template-columns` 지정(번호 56px + 본문). 세로선·테이블 격자 금지.
- **라벨 `.lbl`**: 6px 엠버 점 + 12.5px 텍스트. 파트 번호, 표본 정보(`Pilot · n=480`), 섹션 표시에 쓴다. `.lbl.off`는 회색 점.
- **막대 `.bar`**: 2px 선 막대. 기본 채움은 흰색, 강조 하나만 `i.e`(엠버 그라데이션).
- **타임라인 `.tick`**: 1px 상단선. 현재 단계 하나만 `.tick.on`(엠버 선 + 점), 위에 64px 단계 번호(`01`은 흰색, 나머지 38% 흰색).
- **워드마크·페이지 번호**: Cover는 워드마크 좌상단(`.hd`), 그 외 장은 좌하단(`.ft`). 우하단 `.micro`에 `01 Problem · 03 / 08`. Cover에는 번호가 없다.
- **아이콘**: 쓰지 않는다. 숫자·라벨·헤어라인으로 해결한다.

## 5. 아키타입 (템플릿에 전부 있음)

**덱 `templates/deck.html`**
1. **Cover** — `.flute` 풀블리드. 좌하단 2줄 디스플레이(108px), 그 아래 `.kick` 한 줄("Launch Plan 2027"). 워드마크 좌상단.
2. **Contents** — `.glow.tr`. 좌측 "Contents" 72px + 리드, 우측 `.rows` 목차(엠버 번호는 현재 파트 하나만).
3. **Problem · Stats** — `.glow.bl`. 좌상단 2줄 헤드라인, 우상단 리드 300px, 하단 스탯 카드 3개(top 330px).
4. **Divider** — `.flute.pane`(우측 46%). 좌상단 `.lbl` Part 번호, 좌하단 디스플레이 + 리드 한 줄.
5. **Features** — `.glow.br`. 좌측 헤드라인(강조 한 구절) + 리드, 우측 640px부터 `.rows` 3행.
6. **Metric** — `.glow.tl`. 좌측 200px 히어로 숫자 + 리드, 우측 `.card.solid` 안 막대 4줄(마지막만 엠버).
7. **Roadmap** — `.glow.bl`. 헤드라인 + 리드, 4단계 `.tick`(현재 단계만 on).
8. **Closing** — `.flute.low`. 좌상단 "Thank you" 128px + 한 문장, 하단 연락 3열.

**문서 `templates/doc.html`**: Hero(`.flute`, 560px) → Problem(`.glow.bl.sm`, 카드 3) → Product(글로 없음, 좌 헤드라인 / 우 행) → Evidence(히어로 숫자 + 막대 카드) → Roadmap(`.glow.tr.sm`, 4단계) → Closing(`.flute.low`, 420px). 섹션은 헤어라인으로 구분한다.

## 6. 레이아웃 규칙

- **덱 좌표계**: 좌우 64px, 콘텐츠 top 76px, 푸터 bottom 40px, 콘텐츠 하단 한계 bottom 96px. 모든 블록은 `position:absolute`로 고정 배치한다.
- **헤드라인 줄**: 좌측 2줄 헤드라인 + 우측 리드(폭 300px, top 84px, 왼쪽 정렬 텍스트). 리드는 헤드라인 첫 줄 높이에 맞춘다.
- **비대칭 여백**: 헤드라인과 카드 사이에 120px 이상 빈 블랙을 둔다. 빈 공간이 이 스타일의 고급스러움이다 — 억지로 채우지 않는다.
- **분할**: 좌측 360–440px 텍스트 열 + 우측 `left:520~660px` 블록. 균등 카드는 3개까지, 4개 균등은 Roadmap 한 곳만.
- **줄바꿈은 직접 정한다**: 제목·카드 설명은 `<br>`로 의미 단위에서 끊는다. 숫자·시간은 `white-space:nowrap`(`.num` 기본).
- **문서**: 섹션 padding 72/64, 섹션 사이 1px 헤어라인, 글로는 떨어진 두 섹션에만.

## 7. 카피 규칙

- 헤드라인은 2줄, **긴장 → 해소** 구조로 짧게. 예: "모두가 바쁜데, / 회복하는 사람은 없다", "네 단계로 / 시장에 들어갑니다".
- 영문 디스플레이는 2–4단어(표지·구분장·Contents·Thank you). 본문·설명·카드는 한글.
- 카드 제목은 2–6자 명사형("만성 피로", "수면 부족"), 설명은 2줄 이내.
- 숫자를 앞세운다("68%", "5.9h", "1 in 4", "+31%"). 출처·표본은 `.lbl`로 밝힌다.
- 근거 없는 최상급("세계 최초", "업계 1위")은 쓰지 않는다.

## 8. 금지 사항 (생성형 티가 나는 것)

- 본문 장에 골유리 줄무늬, 한 장에 글로 2개 이상, 덱에 골유리 4장 이상
- `filter:blur`·`backdrop-filter`·`mix-blend-mode`·이미지로 만든 빛, 네온, 흰색에 가까운 과노출 코어
- 엠버 외 유채색(보라·파랑·초록 그라데이션), 엠버로 면 채우기, 오렌지 버튼
- 둥근 카드, 그림자, 테두리 박스, 글래스모피즘, 카드 안의 카드
- 400 이상의 디스플레이, 굵은 한글 헤드라인, 이탤릭, 밑줄, 가운데 정렬 본문
- 이모지, 아이콘 세트, 스톡 사진, 3D 일러스트
- 빈 공간을 불릿·설명 문장으로 채우기, 불릿 5개 이상

## 9. 검수 체크리스트 (렌더 PNG를 보면서)

- [ ] 텍스트가 카드·화면 밖으로 넘치거나 겹치지 않는다. 특히 2줄 디스플레이 끝과 카드 숫자("$1.2T" 같은 긴 값).
- [ ] 한글이 어절 중간에서 끊기지 않고, 숫자·시간이 두 줄로 갈라지지 않는다.
- [ ] 골유리는 덱 3장 이하, 본문 장 글로는 1개 이하이며 위치가 연속으로 같지 않다.
- [ ] 제목 아래가 충분히 어둡다(골유리 장의 좌측·하단). 흰 글자가 밝은 줄무늬 위에 걸치지 않는다.
- [ ] PDF를 열었을 때 줄무늬와 글로가 PNG와 같게 보인다(빛이 사라졌다면 금지 속성을 썼는지 확인).
- [ ] 엠버 텍스트 강조가 장당 1곳이다.
- [ ] 페이지 번호가 `NN / 총장수`로 맞고, 목차 페이지가 실제와 일치한다.
- [ ] Inter와 Pretendard가 로드됐다(숫자 "1"이 세리프 없이 얇게 보여야 한다).
- [ ] 레퍼런스의 브랜드명·로고·슬로건, 의뢰처가 원치 않는 정보가 없다.

## 10. 확장

- **제품 이미지가 필요할 때**: 사진 대신 Divider의 `.flute.pane` 창을 "이미지 자리"로 쓰고, 그 옆에 스펙 `.rows`를 둔다.
- **표가 필요할 때**: `.rows`에 열을 늘리고 강조 행 하나만 숫자를 `--ember-hi`로 칠한다. 행 배경색은 쓰지 않는다.
- **여러 문서 일관성**: 데이터(dict/JSON) + 템플릿 함수로 생성기를 만들면 빛 계획(어느 장에 무엇을)이 흔들리지 않는다.
