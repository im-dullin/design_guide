# Mono Panel Design System

어두운 페이지 위에 큰 라운드 패널을 얹고, 그 안을 타일·필·헤어라인으로 구성하는 에디토리얼 IR덱 스타일입니다. 장식이 아니라 **위계·여백·숫자**로 고급스러움을 만듭니다.

## 0. 작업 순서 (반드시 이 순서)

1. 포맷을 고르고, 템플릿 HTML과 `assets/mono.css`를 **같은 결과물 폴더**에 복사한 뒤 `<link href="../assets/mono.css">`를 `href="mono.css"`로 바꾼다.
   - 슬라이드 덱(16:9, 1280×720): `templates/deck.html`에서 시작
   - 세로 롱페이지(웹뷰·한 장 PDF·모바일 공유): `templates/doc.html`에서 시작
2. 내용을 먼저 슬라이드/섹션 단위로 나눈다. **1장 1메시지**로, 아래 §5 아키타입 중 하나에 배정한다.
3. 템플릿 블록을 복제해 텍스트만 바꾼다. 새 레이아웃을 즉흥으로 만들기 전에 기존 아키타입을 먼저 쓴다.
4. `python3 scripts/render.py <file.html> [out_dir]`로 렌더한다.
5. **반드시 PNG를 열어서 직접 본다.** 덱은 `_check_<name>/sheet.png`(전체)와 개별 `sNN.png`, 문서는 `full.png`. §8 체크리스트로 검수하고, 넘침·겹침·줄바꿈 깨짐을 고친 뒤 다시 렌더한다.

## 1. 원칙 5가지

1. **패널 구조.** 모든 내용은 `--page`(#151515) 위의 라운드 패널(`.p.l` 라이트 / `.p.d` 다크) 안에 둔다. 덱은 패널 inset 18px, radius 30이고, 문서는 패널 사이 간격 12px, radius 28이다.
2. **다크와 라이트를 교차.** 표지·구분장·지표·마무리는 다크, 설명·표·비교는 라이트로 둔다. 같은 톤을 3장 넘게 연속으로 두지 않는다.
3. **액센트는 한 화면에 하나.** 페일 블루 타일(`.tile.s`)은 슬라이드·섹션당 최대 1개로, 가장 중요한 숫자나 해법 하나에만 쓴다. 텍스트 강조는 `.a`(라이트 위 `--blue`, 다크 위 `--sky2`)로 한 구절만 한다.
4. **영문 디스플레이 + 한글 본문.** 큰 제목은 짧은 영문 2~3단어(`.disp`, Inter Tight 400, 자간 -0.045em, 행간 0.92)로 쓰고, 의미는 그 아래 한글 헤드라인과 서브가 전달한다. 라벨은 영문 마이크로(`.micro`: "Problem 01", "Output", "Day 02")로 쓴다.
5. **숫자가 주인공.** 지표는 `.num`(Inter Tight 500, tabular)을 크게 쓰고, 단위는 숫자의 약 40~45% 크기로 붙인다(`48<span style="font-size:28px">k</span>`). 설명은 `.cap` 한 줄로 단다. `.num` 안에는 숫자·영문·기호만 넣는다. 한글 단위(억·명·원)는 `<span style="font-family:Pretendard;font-weight:600">억</span>`처럼 따로 감싼다.

## 2. 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--page` | #151515 | 가장 바깥 배경 |
| `--light` | #ebebe9 | 라이트 패널 |
| `--black` | #0b0b0b | 다크 패널 |
| `--white` | #fff | 라이트 패널 위 흰 타일 |
| `--tile` / `--tile2` | #171717 / #222 | 다크 타일 (`.k`/`.g`) |
| `--ink` / `--sub` | #0d0d0d / #6b6b68 | 본문 / 보조 |
| `--hair` / `--hairD` | rgba(0,0,0,.12) / rgba(255,255,255,.14) | 1px 헤어라인 |
| `--blue` | #2f6bff | 라이트 위 강조 텍스트, 강조 행 |
| `--sky` | #c8dbfb | 액센트 타일, 추천 필 |
| `--sky2` | #9dbdf3 | 다크 위 강조, 구분장 대형 숫자 |
| `--sigbg` | #e7effd | 표의 시그니처 행 배경 |

**이 팔레트 외의 색은 쓰지 않는다.** 유일한 그라데이션은 막대 그래프 채움(`--sky2`에서 `--blue`)이다. 브랜드 색을 꼭 넣어야 한다면 `--blue`, `--sky`, `--sky2` 세 값만 그 브랜드 계열로 바꾸고, 나머지 무채색은 유지한다.

## 3. 타이포 스케일

폰트는 Pretendard(한글·본문)와 Inter Tight(영문·숫자) 두 가지다. `<head>`에 두 링크를 반드시 넣는다(템플릿 참고). 한글은 `word-break:keep-all`로 어절 단위 줄바꿈을 유지한다.

| 역할 | 덱(1280) | 문서(900) | 클래스 |
|---|---|---|---|
| 표지 디스플레이 | 120–124px | 104px | `.disp` |
| 구분장·Thank you | 120–168px | — | `.disp` |
| 섹션 디스플레이 | 64–96px | 56–64px | `.disp` |
| 구분장 파트 번호 | 300px, weight 300, `--sky2` | — | `.num` |
| 한글 헤드라인 | 40px / 600 / -0.045em | 26–30px | `.h` (강조 `.a`) |
| 타일 제목 | 21–24px / 600 | 15.5–22px | inline |
| 대형 숫자 | 44–72px | 40px | `.num` |
| 본문/서브 | 15px | 14.5px | `.sub` |
| 캡션 | 12.5px | 12.5px | `.cap` |
| 라벨 | 12px Inter Tight 500 | 12px | `.micro` |
| 워드마크 | 12px 600 자간 .14em 대문자 | 동일 | `.wm` |

한글 제목은 항상 weight 600에 음수 자간(-0.03~-0.045em)을 준다. 700 이상이나 이탤릭은 쓰지 않는다.

## 4. 컴포넌트

- **필 `.pill`**: 아웃라인 캡슐(1px currentColor). `.sm`은 작은 메타, `.fill`은 핵심 속성 1개(다크 위에선 흰색), `.blue`는 추천·유료 표시다. `.dot`으로 상태 점을 붙인다. 한 줄에 2~4개까지만 둔다.
- **타일 `.tile`**: radius 20(문서 18), padding 22/24. 종류는 `.w` 흰색(라이트 패널 위 기본), `.k` 다크(라이트·다크 패널 모두), `.g` 한 단계 밝은 다크(다크 패널 위), `.s` 페일 블루 액센트다. 타일 구성은 "좌상단 `.micro` 라벨 → 아래쪽 제목/숫자 → `.cap`"이고, 우상단이나 우하단에 `.ico`를 하나 둔다. 내용은 `display:flex;flex-direction:column;justify-content:space-between`으로 위아래에 붙인다.
- **아이콘 칩 `.ico`**: 34px 라운드 사각 안에 18px 선 아이콘. `assets/icons.md` 세트를 쓰고, 타일당 최대 1개만 둔다. CTA 느낌이 필요하면 우하단에 `arrow`를 쓴다.
- **헤어라인 행 `.rows`**: 목차, 표, 스펙, 비교에 쓴다. 자식 div마다 `grid-template-columns`를 직접 지정한다. 세로선, 테이블 테두리, 지브라 줄무늬는 쓰지 않는다.
- **시그니처**: 차별점이 되는 항목만 쓴다. 배지는 `.sigb`(검정 캡슐 + 하늘색 점)다. 표 행에는 `.trow.sig`, 세션 리스트에는 `.row.sig`로 행 전체를 `--sigbg`로 칠한다. 이유는 `.why`(좌측 2px 블루 라인)에 한두 문장으로 쓴다. 문서 전체에서 2~4개를 넘기지 않는다.
- **강조 행 HL**: 시그니처는 아니지만 하이라이트할 행 하나는 시간과 제목만 `--blue` 텍스트로 칠한다.
- **세션 리스트(문서)**: `.ses`(흰 박스) 안에 `.row`(112px 시간 열 + 본문)를 두고, 불릿은 짧은 가로선이다. 도구 태그는 `.tg`(무료)와 `.tg.pd`(유료)로 표시한다. 휴식이나 구분은 `.brk`(점선 구분)로 한다.
- **데이터 시각**: `.bar`(10px 캡슐 막대, 채움은 그라데이션)와 `.dots`(유닛 차트, 10열 × 10행 = `<i>` 100개, 해당 수만큼 앞에서부터 채우고 나머지는 `class="o"`)를 쓴다. 차트 라이브러리는 쓰지 않고 이 두 가지와 큰 숫자로 해결한다.
- **헤더/푸터(덱)**: 헤더 좌측은 항상 워드마크(`.wm`, 로고 대신 프로젝트명 대문자)다. 헤더 우측과 푸터는 장 유형별로 다르다.

  | 장 유형 | 헤더 우측 | 푸터 `.ft` |
  |---|---|---|
  | Cover | `.micro` 문서 종류 + `.pill.sm` 날짜 (번호 없음) | 좌측 한 줄 소개만 |
  | Contents | `NN / TT` | 좌측 문서 제목 · 우측 문서 종류 · 연도 |
  | Divider · Closing | `NN / TT` | 없음 |
  | 그 외 본문 장 | `<span class="micro">01 Overview · NN / TT</span>` (한 span) | 좌측 각주 한 줄 · 우측 문서 종류 · 연도 |

  섹션 라벨의 번호는 Contents·Divider의 파트 번호와 같다. 목차가 없는 짧은 덱이면 내용 묶음 순서대로 `01 Why`, `02 Traction`처럼 직접 붙인다.

## 5. 아키타입 (템플릿에 전부 있음)

**덱 `templates/deck.html`**
1. **Cover**(다크): 좌측 대형 디스플레이 2줄, 필 2개, 한글 제목. 우하단은 2×2 스탯 타일(k, k, s 가로 2칸).
2. **Contents**(라이트): 좌측 "Contents"와 필(“3 Parts · N Pages”), 우측 `.rows` 목차(파란 번호 / 제목 / 캡션 / 페이지).
3. **Divider**(다크): 좌하단 Part 필과 디스플레이, 우상단 300px 파트 번호(`--sky2`), 우하단 파트 내 목차 rows.
4. **Problem→Solution**(라이트): 상단은 좌측 `.h`와 우측 `.sub`. 아래 3열은 각 열 위에 흰 타일(문제), 아래에 k 타일(해법)을 두고, 가운데 해법 하나만 s 타일로 한다.
5. **Metrics**(다크): 영문 디스플레이 제목 아래 g, s, g 타일. 큰 숫자와 도트·막대 차트를 둔다.
6. **Timetable / Roadmap**(라이트): 좌측 330px 열에 필, 대형 숫자(기간: “4w”·“6h”·“12m”·“Q1–Q4”), 목표, 하단 타일. 우측은 흰 타일 표(`.trow`, 시그니처 행 하이라이트)다.
7. **Compare / Pricing**(라이트): 라벨 열 150px, 흰 타일(기본안)과 다크 타일(추천안, `.pill.blue`). 옵션이 3개면 `150px 1fr 1fr 1fr`로 늘리고 추천안 하나만 다크로 둔다. 각 타일 안 행 높이를 52px로 통일해 행끼리 정렬한다.
8. **Closing**(다크): "Thank you" 168px, 한 문장, 하단에 연락 k 타일 + 다음 단계 s 타일.

**문서 `templates/doc.html`**: Hero(다크, 스탯 4타일, Key Strength 줄) → Overview(라이트, 단계 타일 2개와 결과물 흰 타일) → Timeline(라이트, 세션 리스트) → Use Cases(다크, 4열 아이콘 타일, 마지막 1개만 s) → Details + Contact(라이트, 좌측 스펙 행, 우측 연락 타일).

## 6. 레이아웃 규칙

- **덱 좌표계**: 콘텐츠 영역은 left/right 56px, top 92~96px, bottom 64px이다. 복잡한 장은 `position:absolute`로 좌우 블록을 고정 배치해도 된다(템플릿 방식).
- **간격**: 타일 사이 8~14px, 섹션 블록 사이 22~34px. 덱 패널 padding은 44/56, 문서 패널은 40이다.
- **비대칭 분할**: 좌측 330~520px 고정, 우측 가변(`left:420px; right:56px`), 또는 `1.6fr 1fr`, `1.75fr 1fr` 같은 비대칭 그리드를 쓴다. 똑같은 카드를 4개 이상 균등 나열하는 것은 Use Cases 1곳에만 허용한다.
- **정렬**: 헤드라인 줄은 `justify-content:space-between; align-items:flex-end`로 좌측 제목, 우측 서브를 둔다. 서브 폭은 300~330px로 제한한다.
- **줄바꿈은 직접 정한다**: 제목과 타일 문구는 `<br>`로 의미 단위에서 끊는다. 한 줄로 두어야 할 짧은 값(시간, 숫자)에는 `white-space:nowrap`을 준다.

## 7. 카피 규칙

- 헤드라인은 **대비 구조**로 쓴다. 예: "만들 수 있는데, **쓸 만한 건** 안 나옵니다", "누구나 막히는 마지막 10%, **노하우로 뚫어 줍니다**". 강조는 한 구절만 한다.
- 타일 제목은 6~12자의 명사형 또는 단정형으로 쓴다. 설명은 `.cap` 1~2줄로 끝낸다.
- 영문은 디스플레이와 라벨에만 쓴다(`Overview`, `The Difference`, `Use Cases`, `Problem 01`, `Output 02`). 본문과 설명은 한글로 쓴다.
- 숫자를 앞에 세운다(“9시간 뒤 손에 남는 결과물 3가지”, “+38%”).
- 근거가 불분명한 최상급("국내 유일", "업계 최고")은 쓰지 않는다.

## 8. 금지 사항 (생성형 티가 나는 것)

- 이모지, 컬러 아이콘, 3D 일러스트, 스톡 사진
- 배경 그라데이션, 글로우, 네온, 그림자 남발(`box-shadow` 금지), 글래스모피즘
- 보라·초록·주황 등 팔레트 외 색, 한 화면에 액센트 2개 이상
- 모든 요소를 카드로 감싸기, 카드 안의 카드 안의 카드
- 굵은 테두리, 세로 구분선, 테이블 격자
- 가운데 정렬 본문 단락(디스플레이와 Thank you만 예외)
- 길고 설명적인 문장으로 타일 채우기, 불릿 5개 이상
- 700 이상 굵기, 이탤릭, 밑줄

## 9. 검수 체크리스트 (렌더 PNG를 보면서)

- [ ] 텍스트가 타일이나 패널 밖으로 넘치거나 다른 요소와 겹치지 않는다. 특히 긴 영문 디스플레이와 표의 마지막 행.
- [ ] 한글이 어절 중간에서 끊기지 않고, 짧은 값(시간·숫자)이 두 줄로 갈라지지 않는다.
- [ ] 슬라이드·섹션마다 액센트 타일이 1개 이하이고, 다크와 라이트가 교차한다.
- [ ] 큰 빈 공간이 한쪽에만 몰려 있지 않다(표 행 padding으로 높이를 채움).
- [ ] 헤더 페이지 번호가 `NN / 총장수`로 맞고, 목차 페이지 번호가 실제와 일치한다.
- [ ] 폰트가 로드됐다. Inter Tight가 안 보이면 네트워크나 링크를 확인한다.
- [ ] 회사 로고나 개인정보 등 의뢰처가 원치 않는 정보가 빠졌다.

## 10. 확장

- **새 아키타입이 필요할 때**: 기존 블록을 조합한다. 예: 좌측 330px 정보 열 + 우측 흰 타일 / 다크 박스(`.box.k`) 안에 g 타일 3행 / 목업 스테이지(라이트 배경 위 흰 브라우저·폰 프레임).
- **목업**: 결과물 화면은 실제 스크린샷 대신 HTML로 간단히 그린 브라우저 프레임(회색 바 + URL 캡슐)이나 폰 프레임을 쓰고, 라이트 바탕(`--light`) 위에 둔다.
- **여러 문서 일관성**: 데이터(dict/JSON)와 템플릿 함수로 생성기를 만들면 문서를 여러 개 만들어도 톤이 흔들리지 않는다.
