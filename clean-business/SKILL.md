# Clean Business Design System

오프화이트와 니어블랙 두 가지 바탕 위에 레귤러 굵기의 큰 영문 제목을 두고, 아웃라인 필·원형 화살표·1px 헤어라인으로 나머지를 정리하는 기업 덱 스타일입니다. 액센트 색이 없습니다. **크기 대비, 여백, 선**으로만 위계를 만듭니다.

## 0. 작업 순서 (반드시 이 순서)

1. 포맷을 고르고, 템플릿 HTML과 `assets/clean-business.css`를 **같은 결과물 폴더**에 복사한 뒤 `<link href="../assets/clean-business.css">`를 `href="clean-business.css"`로 바꾼다.
   - 슬라이드 덱(16:9, 1280×720): `templates/deck.html`에서 시작
   - 세로 롱페이지(웹뷰·한 장 PDF·모바일 공유): `templates/doc.html`에서 시작
2. 내용을 슬라이드/섹션 단위로 나눈다. **1장 1메시지**로, 아래 §5 아키타입 중 하나에 배정한다.
3. 라이트(`.lt`)와 다크(`.dk`) 중 각 장의 톤을 정한다. 전체를 라이트로 하고 다크는 구분장·지표·마무리에만 쓰는 것이 기본이다. 사용자가 "다크 버전"을 원하면 모든 `.lt`를 `.dk`로, `.panel.dk`를 `.panel.lt`(또는 `.dk2`)로 바꾸면 같은 레이아웃이 그대로 뒤집힌다.
4. 템플릿 블록을 복제해 텍스트만 바꾼다. 새 레이아웃을 즉흥으로 만들기 전에 기존 아키타입을 먼저 쓴다.
5. `python3 scripts/render.py <file.html> [out_dir]`로 렌더한다.
6. **반드시 PNG를 열어서 직접 본다.** 덱은 `_check_<name>/sheet.png`(전체)와 개별 `sNN.png`, 문서는 `full.png`. §9 체크리스트로 검수하고, 넘침·겹침·줄바꿈 깨짐을 고친 뒤 다시 렌더한다. `_check_` 폴더는 결과물에 포함하지 않는다.

## 1. 원칙 5가지

1. **바탕은 두 가지뿐.** 라이트 `--paper`(#F4F4F2)와 다크 `--night`(#121212). 클래스 `.lt` / `.dk`를 슬라이드·섹션·패널 어디에든 붙이면 배경·글자·선 색이 함께 바뀐다(중첩 가능). 같은 레이아웃을 두 톤으로 쓸 수 있게 만드는 것이 이 시스템의 핵심이다.
2. **제목은 굵게가 아니라 크게.** 영문 디스플레이(`.disp`, Inter Tight 400, 자간 -0.05em, 행간 0.92)는 표지 156px까지 키우되 굵기는 항상 400이다. 한글 헤드라인도 500을 넘기지 않는다.
3. **액센트 색이 없다.** 강조는 ① 크기, ② 채운 필(`.pill.on`) 1개, ③ 진한 윗선(헤어라인 대신 `var(--fg)` 1px) 1개로만 한다. 로고 별표의 회색(`--mark`)이 유일한 유채색 기미이고, 다른 곳에는 쓰지 않는다.
4. **반대 톤 라운드 패널 하나.** 화면에 무게가 필요하면 바탕과 반대 톤의 `.panel`(radius 24)을 하나 둔다. 라이트 바탕엔 `.panel.dk`, 다크 바탕엔 `.panel.lt` 또는 `.panel.dk2`. 패널은 화면당 최대 1개이고, 그 안은 헤어라인 행 리스트로 채운다(목차·토큰·Do&Don't).
5. **라벨 위, 값 아래.** 정보는 카드가 아니라 메타 행(`.meta`: 작은 회색 `.lbl` 위에 `.val`)과 헤어라인 행(`.rows`)으로 늘어놓는다. 상단 바와 하단 저작권 줄이 매 장의 틀을 잡는다.

## 2. 토큰

| 토큰 | 값 | 용도 |
|---|---|---|
| `--paper` | #F4F4F2 | 라이트 바탕 |
| `--night` | #121212 | 다크 바탕, 라이트 위 패널 |
| `--night2` | #1C1C1C | 다크 바탕 위 패널(`.dk2`) |
| `--ink` / `--snow` | #111111 / #ECECE8 | 라이트 위 / 다크 위 본문·제목 |
| `--gray` / `--gray2` | #76766F / #8C8C86 | 라이트 위 / 다크 위 라벨·캡션 |
| `--mark` | #A3A9A1 | 로고 별표 전용 |

테마 클래스가 만드는 변수: `--bg`, `--fg`, `--sub`, `--hair`(1px 선, 라이트 rgba(17,17,17,.13) · 다크 rgba(255,255,255,.14)), `--line`(필·원형 버튼 테두리), `--ph`(이미지 자리 바탕). 컴포넌트는 항상 이 변수를 쓰므로 톤을 바꿔도 따로 손댈 곳이 없다.

**이 팔레트 외의 색은 쓰지 않는다.** 브랜드 색을 꼭 넣어야 하면 `--mark` 한 값만 브랜드 색으로 바꾸고 로고에만 쓴다.

## 3. 타이포 스케일

폰트는 Pretendard(한글·본문)와 Inter Tight(영문 디스플레이·라벨·숫자) 두 가지다. `<head>`에 두 링크를 반드시 넣는다(템플릿 참고). Inter Tight는 원본 레퍼런스의 네오 그로테스크(Helvetica Now Display · Neue Haas Grotesk 계열)를 대신하는 무료 서체다. 한글은 `word-break:keep-all`로 어절 단위 줄바꿈을 유지한다.

| 역할 | 덱(1280) | 문서(900) | 클래스 |
|---|---|---|---|
| 표지·마무리 디스플레이 | 156px / 400 | 104px | `.disp` |
| 목차·구분장 디스플레이 | 104–112px | 60px | `.disp` |
| 섹션 디스플레이 | 72px | 64px | `.disp` |
| 대형 숫자 | 64–72px / 400, 단위 40~45% | 64px | `.num` |
| 한글 헤드라인 | 30–34px / 500 / -0.045em | 27px | `.h` |
| 항목 제목 | 19px / 500 | 17–19px | `.t` |
| 본문/서브 | 14.5px, 행간 1.7 | 14.5px | `.sub` |
| 캡션 | 12.5px | 12.5px | `.cap` |
| 라벨 / 값 | 12px 400 / 13.5px 500 | 동일 | `.lbl` / `.val` |
| 필 | 11px 500 대문자 자간 .04em | 동일 | `.pill` |
| 인덱스 | 15px "(1)" | 동일 | `.idx` |
| 저작권 줄 | 9.5px 500 대문자 | 동일 | `.copy` |

굵기는 400~500만 쓰고, 600은 로고 이름과 저작권 줄의 브랜드명(`.copy b`)에만 쓴다. 이탤릭·밑줄은 쓰지 않는다.

## 4. 컴포넌트

- **상단 바 `.tb`**: 좌측 `.side` = 로고(`.logo`: 별표 SVG + 이름) + 문서 종류 필. 우측 `.side` = 필 + 원형 화살표(`.cbtn`). 본문 장에서는 좌측 필에 섹션명(`01 About`), 우측에 페이지(`.pg` "04 / 08")만 둔다.
- **필 `.pill`**: 1px 아웃라인 캡슐, 영문 대문자. `.sm`은 작은 태그(`Service 01`), `.ko`는 한글 필, `.on`은 채운 필(현재 단계·Do 1개)로 화면당 1개. 한 줄에 3개까지만 둔다.
- **원형 버튼 `.cbtn`**: 1px 원 안에 화살표. 크기 `.cbtn`(40) · `.lg`(56) · `.xl`(76), 방향 기본 ↘ · `.ne` ↗ · `.sw` ↙ · `.nw` ↖. 대형 제목 옆이나 상단 바 우측 끝, 행 끝에 한 화면 1~3개만. 마크업은 `assets/icons.md`.
- **헤어라인 `.hr` · 행 리스트 `.rows`**: 1px `--hair`. `.rows` 자식 div마다 `grid-template-columns`를 직접 지정한다. 기본은 행 사이에만 선이 있고, `.rows.open`은 위아래 끝에도 선을 긋는다. 세로선·테이블 격자·지브라 줄무늬는 쓰지 않는다.
- **메타 행 `.meta`**: `1fr 1.6fr 1fr` 3열, 각 칸 `.lbl` 위 `.val`. 표지·마무리 하단에 `.hr` 바로 아래 둔다(Contact / Date / Website).
- **패널 `.panel`**: radius 24(문서 22), 바탕과 반대 톤. 덱에서는 상·우·하 16px 여백으로 화면 한쪽(폭 640~676px)을 채운다. 안에는 `.rows`를 `grid-template-rows:repeat(N,1fr)`로 균등 배분한다.
- **목차 행**: `150px 1fr 40px` = 필 `Section 1` · `.t` 제목 · `.idx` "(1)".
- **숫자 열**: 윗선 1px → `.lbl` → `.num` 72px → `.cap`. 강조할 한 칸만 윗선을 `var(--fg)`로, 라벨을 `--fg` 색으로 바꾼다.
- **타임라인**: 가로 `.hr` 위에 11px 점. 현재 단계만 채운 점 + `.pill.sm.on` "Now", 나머지는 빈 원.
- **이미지 자리 `.ph`**: `--ph` 단색 + 좌하단 "이미지 자리" 라벨(`data-label`로 크기·내용 표기). radius 18, 풀블리드는 `.ph.sq`. 실제 사진은 `<div class="ph"><img src="photo.jpg"></div>`로 넣으면 `object-fit:cover`와 흑백 필터가 자동으로 적용되고 라벨이 사라진다. 사진은 결과물 폴더에 함께 두고 상대경로로 건다.
- **하단 줄 `.ft`**: 좌측 `.copy`(`<b>©2026 Brand.</b> All rights reserved.` 또는 출처), 우측 `.pg`(문서 제목 또는 페이지). 목차 장은 저작권 줄을 좌상단에 둔다.

## 6. 레이아웃 규칙

- **덱 좌표계**: 좌우 64px. 상단 바 top 40px, 본문 top 132px, 하단 줄 bottom 34px, 본문 bottom 84px. 표지 제목 top 212px, 하단 메타 bottom 64px. 복잡한 장은 `position:absolute`로 블록을 고정 배치한다(템플릿 방식).
- **문서**: 900px 폭, 섹션 padding 56px. 라이트 섹션끼리는 1px 헤어라인으로 나누고, 다크 섹션은 문서 전체에서 2개까지만.
- **대각선 배치**: 큰 제목은 좌하단, 패널이나 이미지는 우측(또는 반대)에 둬서 화면을 대각선으로 쓴다. 표지만 제목을 좌상단 중간 높이에 둔다.
- **여백을 남긴다**: 표지 제목과 메타 사이처럼 비어 있는 구간은 채우지 않는다. 다만 빈 공간이 화면 한쪽 절반 이상을 차지하면 항목을 키우거나 행 padding으로 높이를 맞춘다.
- **정렬**: 제목 줄은 `display:flex;justify-content:space-between;align-items:flex-end`로 좌측 제목, 우측 서브(폭 300~330px, 우측 정렬) 또는 원형 버튼.
- **줄바꿈은 직접 정한다**: 제목과 서브는 `<br>`로 의미 단위에서 끊는다. 한 줄로 두어야 할 짧은 값에는 `white-space:nowrap`.

## 7. 카피 규칙

- 영문은 디스플레이(2~3단어: `Our Contents`, `Key Numbers`, `What We Do`, `Thank You`), 필, 라벨(`Contact`, `Date`, `Founded`)에만 쓴다. 의미 전달은 한글 헤드라인·제목·캡션이 한다.
- 한글 헤드라인은 "누구에게 무엇을 해 주는 누구인지"를 단정형 한 문장(2~3줄)으로 쓴다. 과장된 수사 대신 사실을 쓴다.
- 항목 제목은 6~10자 명사형(“운영 데이터 진단”), 캡션은 한 줄.
- 숫자는 근거(기준 시점·표본)를 하단 줄에 밝힌다. "국내 유일", "업계 최고" 같은 최상급은 쓰지 않는다.
- 목차·섹션 번호는 `Section 1` 필과 `(1)` 인덱스로 통일한다.

## 8. 금지 사항 (생성형 티가 나는 것)

- 포인트 컬러(파랑·보라·초록 등), 그라데이션, 글로우, 그림자(`box-shadow` 금지), 글래스모피즘
- 이모지, 컬러 아이콘, 아이콘 칩, 3D 일러스트, 스톡 사진 느낌의 컬러 사진(사진은 흑백 한 컷)
- 볼드 디스플레이(600 이상), 이탤릭, 밑줄
- 모든 요소를 카드로 감싸기, 패널 2개 이상, 패널 안의 패널
- 굵은 테두리, 세로 구분선, 테이블 격자
- 가운데 정렬 본문 단락
- 길고 설명적인 문장, 불릿 5개 이상, 한 화면 필 4개 이상

## 9. 검수 체크리스트 (렌더 PNG를 보면서)

- [ ] 156px 제목이 우측 64px 여백 안에 들어온다(한 줄 15자 내외가 한계, 넘으면 2줄로 끊거나 크기를 줄인다).
- [ ] 텍스트가 패널·이미지 자리 밖으로 넘치거나 다른 요소와 겹치지 않는다. 특히 패널 마지막 행과 하단 줄.
- [ ] 한글이 어절 중간에서 끊기지 않고, 짧은 값(전화번호·날짜·숫자)이 두 줄로 갈라지지 않는다.
- [ ] 화면마다 채운 필·진한 윗선·패널이 각각 1개 이하다. 팔레트 외 색이 없다.
- [ ] 페이지 번호 `NN / 총장수`와 목차 `(N)`이 실제와 맞는다.
- [ ] 폰트가 로드됐다. Inter Tight가 아닌 기본 산세리프로 보이면 링크·네트워크를 확인한다.
- [ ] 이미지 자리가 남아 있다면 의도한 것인지 확인하고, 실사진은 흑백으로 들어갔다.
- [ ] 의뢰처가 원치 않는 로고·개인정보가 빠졌다.

## 10. 확장

- **새 아키타입**: 기존 블록을 조합한다. 예: 좌측 대형 제목 + 우측 패널 안 비교 행(`120px 1fr 1fr`) / 풀블리드 이미지(`.ph.sq` inset 0) 위 우상단 저작권 줄 + 좌하단 흰 제목 / 팀 소개 = 4열 이미지 자리(정사각) + 이름 `.t` + 역할 `.cap`.
- **다크 버전 덱 전체**: 사용자가 원하면 같은 HTML을 복제해 `.lt`↔`.dk`, `.panel.dk`→`.panel.dk2`로 일괄 치환한다. 레이아웃은 손대지 않는다.
- **여러 문서 일관성**: 데이터(dict/JSON)와 템플릿 함수로 생성기를 만들면 문서를 여러 개 만들어도 톤이 흔들리지 않는다.
